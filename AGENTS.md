## Ajudan project conventions

Ajudan onboards a business through an AI interview, designs a team of AI teammates, and runs them. The office view shows them working.

- **Processes:** `pnpm dev` runs the Next.js app and the worker (`worker/index.ts`). **All Claude calls happen in the worker**, never in Next.js. The web app only reads and writes SQLite and enqueues jobs (`enqueueJob` in `src/lib/jobs.ts`).
- **LLM:** call models only through `runAgent()` in `src/lib/claude.ts`. On the default backend it wraps the Claude Agent SDK (headless Claude Code with the local login; default model `MODELS.main`, claude-opus-5-5). A business on OpenRouter or Ollama (Business → AI backend, `src/lib/backend.ts`) runs on the AI SDK engine in `src/lib/agent/` instead: same options, Claude Code-named built-in tools, MCP servers bridged, `canUseTool` checked per call, Bash in `@anthropic-ai/sandbox-runtime`, sessions in `~/.ajudan/agent-sessions`. New `runAgent` options must work on both.
- **Business folders:** one business = one folder (default `~/Ajudan/<Name>/`) holding `ajudan.db`, `teammates/<name>/`, `work/*.md`, `browser/` and `backups/`. Only the open folder (`~/.ajudan/config.json`, see `src/lib/folders.ts`) is active, and the worker pauses and requeues jobs when you switch. Use the helpers in `src/lib/paths.ts` (`dataDir()`, `resolveWorkspace()`, `workDir()`); never hard-code `./data`. `db` from `@/db` always means the open folder's database. Set `AJUDAN_DATA_DIR` to pin one folder (tests, scripts).
- **DB:** SQLite with Drizzle. The schema is in `src/db/schema.ts`. To change it: edit the schema, run `pnpm db:generate` (writes a migration in `drizzle/`), then `pnpm db:migrate`. **Never use `drizzle-kit push`**: on SQLite it rebuilds tables and cascade-deletes rows. `db:migrate` backs up to `data/backups/` first and refuses to finish if rows were lost. Search uses trigram FTS5 tables (`*_fts`, `drizzle/0020_search.sql`, `src/lib/search.ts`) kept in step by triggers; drizzle-kit can't see them, so a migration that rebuilds `context_pages`, `contacts` or `deliverables` must recreate those triggers. 
- **Usage limit:** `runAgent()` throws `UsageLimitError` when Claude's usage is used up. Handlers rethrow it (don't mark work failed); the worker requeues the job and the team "rests" (`src/lib/rest.ts`, shared `~/.ajudan/rest.json`) until the reset, running only token-free jobs (human teammates). The owner can answer customers on the Customer Desk (`/b/[id]/desk`, `src/lib/desk.ts`) meanwhile.
- **Workspace** (`docs/HYBRID-PLAN.md`; token-free): `/b/[id]/home`, `/b/[id]/docs` (Docs are deliverables), `/b/[id]/library` (files in `media/` plus the `assets` table: title, note, tags, album, star; `src/lib/assets.ts`, shown to teammates by `list_media`), `/b/[id]/contacts` (`src/lib/contacts.ts`, feeds `search_contacts` and WhatsApp name lookup), `/b/[id]/trash`. Shared frame and controls: `src/components/workspace-ui.tsx`; "Ask a teammate": `src/components/plan-task.tsx` + `planTask` in `src/app/b/[id]/actions.ts`. Deleting a doc, deliverable, library file or contact soft-deletes it (`deleted_at`, `src/lib/trash.ts`): every list, search and tool must leave `deleted_at` rows out. Links between objects: `src/lib/links.ts`; change snapshots: `src/lib/object-history.ts`; what teammates may do per collection: `src/lib/agent-access.ts`.
  - **Docs:** one list over deliverables + Context pages (`src/lib/docs.ts`, `docs-list.ts`). Folders are `deliverables.folder` paths (`docs-folders.ts`); @mentions are `[Name](ajudan://<type>/<id>)` links reconciled into `links` on owner save (`docs-mentions.ts`); templates in `docs-templates.ts`; export at `/api/b/[id]/docs/[docId]/export?format=md|html|print`.
  - **Library:** `listLibrary(id, { team: true })` adds `work/images/` and `work/videos/` as source "team" (organize/trash accept them via `isOrganizablePath`; `isLibraryPath` stays `media/` only). Smart albums are saved filters in `<folder>/library-views.json` (`library-views.ts`, rules in `library-filter.ts`). Pass `by` to `organize()` to record history.
  - **Contacts:** timeline `contact-timeline.ts`, duplicates/merge `contact-duplicates.ts`, vCard `contact-vcard.ts`, segments in `<folder>/contact-segments.json` (`contact-segments.ts`, matching in `contact-filters.ts`). Follow-ups are columns (`dueFollowUps()` in `contacts.ts`); logged interactions are `object_history` entries with an `interaction` snapshot.
  - **History & Trash:** an `object_history` snapshot is the object AFTER the change; updates may carry `snapshot.before` and teammate updates must (Undo in the Inbox writes it back; `restoreVersion` in `src/lib/object-history.ts`). Trash purges items older than 30 days daily (`worker/maintenance.ts`). Home's "New from the team" state lives in `<folder>/home-review.json` (`src/lib/home.ts`).
  - **Teammate tools:** `search_workspace`/`search_docs`/`search_media`, `create_doc`, `link_objects`/`unlink_objects`, `tag_objects` in `worker/workspace-tools.ts` (ranking in `src/lib/workspace-search.ts`); contact tools in `worker/contact-tools.ts`. Change rules are in `src/lib/workspace-access.ts` (read = look only; suggest = own or other teammates' objects; write = the owner's too). Every teammate write sets `created_by`/`updated_by` to "teammate:<id>" and calls `recordHistory` with `before`.
- **Studio** (`/b/[id]/studio/video`, `/studio/audio`): video/audio edits (`edits` table, spec in `src/lib/edits.ts`) render with ffmpeg in the `render_edit` worker job (`worker/edits.ts`), which runs while the team rests.
- **Live updates:** the worker writes `activity_events` with `logEvent()` (`src/lib/events.ts`). The browser gets them from `/api/b/[id]/events` over SSE. Use `<LiveRefresh businessId>` or `useActivity()` from `src/components/live.tsx`.
- **Pages (Next 16 + Cache Components):** `page.tsx` is a non-async component that renders `<Suspense fallback={<PageSkeleton/>}><Content params={props.params}/></Suspense>`. `Content` is async, awaits params, and reads data through helpers that `await connection()` first (see `src/lib/data.ts`). Mutations are Server Functions (`'use server'`) in a colocated `actions.ts`, followed by `revalidatePath`/`refresh()`. Params and route types: `PageProps<'/b/[id]'>`, `LayoutProps`, `RouteContext`.
- **UI:** use the primitives in `src/components/ui.tsx` and the theme tokens (`bg-surface`, `border-line`, `text-muted`, `bg-accent`). Tailwind v4.
- **Media:** owner uploads live in `<folder>/media/`; tasks carry them in `tasks.attachments` (folder-relative `media/…` / `work/…` paths, see `src/lib/media.ts`). The files route serves only `work/` and `media/`. Teammate skills live in `agent-plugins/ajudan-video/` (loaded with `plugins`/`skills` in `runAgent`; `settingSources: []` means `~/.claude` is never read). Keep Remotion packages pinned to one identical version. Folder listings read the disk; slow per-file details (markdown titles, ffprobe results) are cached in `file_meta` keyed by size + mtime (`src/lib/file-meta.ts`), and gallery tiles use `thumbUrl()` (`src/lib/file-urls.ts`, thumbnails in `<folder>/.cache/thumbs/`), never the original.
- **Desktop app:** `electron/main.cjs` runs one `next start` + worker per business window with `AJUDAN_DATA_DIR` pinned and `AJUDAN_APP=1` (`src/lib/app-mode.ts`); the Businesses window has no worker. Folder actions return `openDir` in the app and the page calls `window.ajudan.openFolder` (`src/lib/app-bridge.ts`). Workers take `<folder>/.worker.lock` (`src/lib/worker-lock.ts`), so never run two on one folder.
- **Voice notes:** incoming ones are transcribed by whisper.cpp (`src/lib/speech.ts`). Replies can go out as voice notes (Business → WhatsApp → Voice replies, `businesses.voiceReplies`): `sendToHuman` in `worker/humans.ts` makes one with OmniVoice (`src/lib/voice.ts`, a shared local server `scripts/voice-server.py` in `~/.ajudan/voice`, set up by `pnpm voice:setup`) and sends it with `wacli send voice`; the text always goes too, approval requests stay text (`voice: false`). Token-free. OmniVoice weights are CC-BY-NC.
- **Credentials & abilities:** never put secrets in prompts, files or the DB; use `src/lib/secrets.ts` (Keychain) and `{{secret.NAME}}` in `http_request`. New teammate abilities should be requestable (`request_capability`, `src/lib/capabilities.ts`) rather than only a switch the owner has to find.
- **Code repositories:** the owner connects local git folders on Business → Repositories (`repositories` table, `src/lib/repos.ts`). Teammates with `repoAccess` (Tech Lead, Code Analyst, or switched on) read them read-only through the file tools (`.git/`, `.env`, keys stay closed) and use GitHub issues through the `github` MCP server (`worker/github-tools.ts`). `gh` runs only in the worker with the owner's login, never in a teammate's sandbox; `create_issues` is outward and takes the whole backlog in one approval.
- **Checks:** `pnpm typecheck`, `pnpm lint`.
